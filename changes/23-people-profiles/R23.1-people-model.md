## Spec

**Problem:** People's names live in three unconnected places: the e-board array in
`EboardSection.tsx`, free-text `lead` strings in 13 subteam files (`"Thomas Kamyszek & Kanika
Syal"`), and (in unmerged set 17) a project leadership list. A person with several roles is typed
once per role, so a rename, a new photo, or a role change has to be found and repeated by hand,
and nothing can show "everything this person does".

**Approach:** one typed module, `src/content/people.ts`, next to `currentInfo.ts` (the existing
home for hand-edited site content).

```ts
export type PersonId = "kanika-syal" | "thomas-kamyszek" | ...;   // kebab-case full name

export type EboardPosition =
  | "President" | "Vice President" | "Treasurer" | "Outreach Coordinator"
  | "Social Media Coordinator" | "Webmaster" | "EGC Representative" | "SEDS Representative";

export type SubteamId =
  | "cubesat/structures" | "cubesat/thermal" | ... | "robotics/mechanical" | ...
  | "weather-balloon/software";

export type Role =
  | { kind: "eboard"; position: EboardPosition }
  | { kind: "project"; project: ProjectId; position: "Project Manager" | "Chief Engineer";
      scope?: "Internal" | "External" }
  | { kind: "subteam-lead"; subteam: SubteamId };

export interface PersonPhoto { src: string; width: number; height: number; position?: string; }

export interface Person {
  id: PersonId;
  name: string;
  roles: Role[];          // at least one
  photo?: PersonPhoto;    // absent -> UserRound placeholder (R14.1 pattern)
  major?: string;
  bio?: string;           // never invented; omitted until the person supplies one
  discord?: string;       // shown only with the person's consent (_set.md OQ1)
}
```

- `people: Person[]` holds everyone currently named anywhere on the site (8 e-board, 6 project
  executives from set 17, 13 subteam leads; with overlaps that is about 22 records).
- Selectors, also exported: `eboard()` (ordered by a single `EBOARD_ORDER` array, which is the
  display hierarchy set 14 established), `projectLeadership(project)` (Project Manager(s), then
  Chief Engineer; Internal before External), `subteamLeads(subteam)`, and
  `roleLabel(role)` for display ("President", "Robotics · Chief Engineer",
  "Project Manager · Internal", "Robotics · Mechanical Lead").
- Each `PersonId`, `EboardPosition`, and `SubteamId` is a string-literal union, so a typo in a
  role or a lead reference fails `tsc` instead of rendering a blank.
- `Subteam` (in `SubteamModal.tsx`) gains `id: SubteamId` and loses the free-text `lead` and
  `leadLabel`. The modal computes both from `subteamLeads(id)`: names joined with " & ",
  "Lead" for one person, "Leads" for more. Visible text is unchanged.
- `EboardSection.tsx` renders `eboard()` instead of its local array. `hometown` and `dreamjob`
  (always empty, never rendered) are dropped. `major` moves to the person.
- Invariant checks run at module load in dev (`import.meta.env.DEV`): every person has at least
  one role, ids are unique, each e-board position is held by exactly one person, and every
  `SubteamId` has at least one lead. A violation throws, so `pnpm dev` and the Playwright smoke
  surface it immediately. Production builds skip the checks.

- **Dead code removal first** (`_set.md` OQ6): delete `src/routes/designLab/` and
  `src/components/CubesatSubteams.tsx`. Confirm with grep that nothing imports either before
  deleting, and run the grep against a file known to be imported to prove it finds imports.

**Not in scope:** visual changes (R23.2 to R23.4). This step is a pure refactor: the home grid and
all subteam cards and modals must look exactly as they do on main.
