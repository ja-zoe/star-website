# R23.5 - Team page

**Status:** not started
**Files:** new `src/routes/team/TeamPage.tsx`; `src/App.tsx`; `src/components/Navbar.tsx`;
`src/routes/home/EboardSection.tsx`; `scripts/prerender-project-routes.mjs`

## Spec

**Problem:** E-board members appear on the home page and project leadership on each project page,
but there is no single place to see everyone who runs STAR, and subteam leads appear only as
text inside subteam cards. The user asked for both the profile dialog (R23.4) and a dedicated
team page in this set (`_set.md` OQ2).

**Approach:**

- **Route `/team`**, lazy-loaded like the project routes, with per-route `<Seo>` (title
  "Team | STAR", description). It is a normal SPA route, so the existing `.htaccess` fallback
  serves deep links.
- **One card per person** (the profile-per-person principle): everyone in `people`, each once.
  Order: e-board in `EBOARD_ORDER`, then project executives by project (CubeSat, Robotics,
  Weather Balloon) and leadership order, then remaining subteam leads by project, then name.
  Cards reuse `PersonCard`: photo or placeholder, name, primary role (the first role in that
  order), and "+N role(s)" when there are more. Clicking opens the R23.4 profile dialog with the
  same `#person/<id>` hash.
- **Filters:** a single-select chip row: All, E-board, CubeSat, Robotics, Weather Balloon. A
  project filter matches anyone with a project role or a subteam lead role in that project. The
  state lives in the query string (`/team?group=robotics`), so filtered views are shareable and
  survive reload; an unknown value falls back to All. The chips are real buttons with
  `aria-pressed`, and the result count is announced politely (`aria-live`).
- **Entry points:** the navbar "Eboard" item becomes "Team" -> `/team` (desktop and mobile
  menus; active when on `/team`). The home "Meet E-board" section keeps its grid and gains a
  "Meet the full team" link to `/team`.
- **Prerender:** `scripts/prerender-project-routes.mjs` emits `team.html` with the route's
  title, description, canonical URL, and a share card in STAR red, and adds `/team` to
  `sitemap.xml`, matching what the three project routes get.
- **Layout:** the grid is 2 columns on mobile, 3 at `md`, 4 at `lg`. It uses the design-system
  tokens and the existing dark/red identity. Static: no new continuous motion.
