## Spec

**Problem:** A card can show only the role relevant to its section (Kanika appears as President
on the home page), so nobody can see that she also leads Robotics Mechanical. The user asked for a
profile per person that collects all of their roles, description, Discord handle, and picture.

**Approach:**

- Every person card (home e-board grid, project leadership band) becomes a button that opens a
  profile dialog built on the existing Radix `Dialog` (`src/components/ui/dialog`). No new
  dependency.
- **Deep link** by URL hash `#person/<person-id>`, the same hash-driven `open` state as
  `SubteamModal`. Closing restores the URL with `replace` and returns focus to the card. A hash
  for an unknown id opens nothing. Subteam and section hashes keep working (prefixed namespace).
- **Contents**, each block only when present: photo (or placeholder), name, every role as a chip
  via `roleLabel` (e-board first, then project, then subteam lead), major, bio, Discord handle
  (OQ1). For people without a photo, a short muted line: "Photo coming soon".
- **Cards hint at more roles.** When a person has roles beyond the one the card shows, the card
  gets a small "+N role(s)" line so the extra roles are discoverable before opening.
- **Motion and a11y:** dialog entry follows the existing dialog animation and is static under
  reduced motion. Esc and the close button dismiss it. The title is the person's name; the
  description lists their roles.
