## Spec

**Problem:** Five new portraits arrived as iPhone HEIC (Sasho, Thomas, Natalia, Kanika, Jordan).
Photo files are named by first name under `public/eboard/`, which stops fitting once project
executives have photos and will collide on a repeated first name. The optimizer's `PORTRAITS`
list still names three departed members. Existing photos are 3:2 landscape, hand-framed per
person with an `objectPosition` and a blanket `scale-125`. The new ones are 3:4 portrait, so the
same zoom would crop their heads.

**Approach:**

1. **HEIC conversion stays outside the repo.** sharp's prebuilt libvips reads AVIF but not HEVC
   HEIC, and Ubuntu's libheif 1.17 rejects these files (iOS 18 `tmap` gain-map brand). They were
   converted with `pillow-heif` 1.8.0 (libheif 1.23.4) in a scratch virtualenv: JPEG quality 95,
   4:4:4 chroma, Display P3 ICC profile kept, EXIF dropped (rotation is already applied to the
   pixels; EXIF can carry GPS). Document this in the script header so the next batch from the
   Drive follows the same path. No Python dependency is added to the project.
2. **Files keyed by person id.** Sources become `scripts/source-images/<person-id>.jpg`, outputs
   `public/people/<person-id>.webp`. Existing photos are renamed with `git mv` (Julian, Praneeth,
   Nila, Aayushi). Kanika's old source and the three departed members' sources move to
   `scripts/source-images/retired/` (kept in git, not regenerated). `PORTRAITS` lists ids.
3. **Color.** sharp converts the embedded P3 profile to sRGB on output. Verify it rather than
   assume it: compare a skin-tone sample from the WebP with a reference that Pillow `ImageCms`
   converts from P3 to sRGB. A naive conversion that drops the profile would differ visibly
   (more desaturated).
4. **Photo metadata in the model.** Each `photo` records its real output `width`/`height` (the
   script prints them) instead of the current hard-coded `964x640` on every `<img>`.
5. **Consistent framing.** Replace the blanket `scale-125` plus ad-hoc `styleAdjustments` with a
   per-photo `position` (and optional `scale`) in `PersonPhoto`, tuned so the faces sit at a
   similar size and height across the grid, old landscape and new portrait photos mixed. Tune by
   screenshot at both breakpoints.
6. `VisualDirectionLab.tsx` (unrouted, see `_set.md`) gets its import paths updated so it keeps
   type-checking. Nothing else changes there.
