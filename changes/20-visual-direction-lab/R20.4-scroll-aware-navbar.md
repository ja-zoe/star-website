# R20.4 — Scroll-aware navbar section state

**Status:** done
**Files:** `src/components/Navbar.tsx`, `src/hooks/useActiveNavigation.ts`, `src/App.css`

## Spec

**Problem:** The fixed navbar changes its underlay after scrolling but does not communicate which
home section is currently in view. Users lose orientation on the long landing page, and project
detail routes do not identify Projects as the current navigation area.

**Approach:** Add a client-only `useActiveNavigation` hook that observes scroll, resize, route, and
home-content mount changes. On `/`, choose the section nearest a viewport-relative activation line,
independent of DOM/nav ordering, while leaving the hero unselected. On project detail routes, return
Projects. Expose the result through `aria-current` on the existing desktop and mobile controls without
changing the user's rounded controls, spacing, CTA, or navbar geometry. Use one full-pill glow language:
the active section gets a persistent deep STAR-red halo while a separately hovered/focused item gets a
brighter coral-red halo, allowing both states to be visible at once. Scrolling never rewrites the URL or
browser history.
