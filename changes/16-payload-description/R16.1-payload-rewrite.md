# R16.1 — Payload subteam description rewrite

**Status:** done
**Files:** `src/routes/cubesat/subteam-descriptions/Payload.tsx`

## Spec

**Problem:** `Payload.tsx` feeds a `Subteam` object (`summary` + 5 `responsibilities`)
into `SubteamModal` (`src/components/SubteamModal.tsx`). The current copy frames Payload
as a build-and-test subsystem team (design/development, environmental survival,
mechanical/electrical interfaces, data & operations, test & calibrate) — it undersells
what the team actually does. Payload runs the fuel-slosh-in-microgravity experiment
top to bottom: it designs the instrument, writes the flight software that talks to the
satellite's OBC and to ADCS, builds the ground-side analysis pipeline, and owns the
technical architecture/strategic calls (reference frames, orbit/attitude modeling,
initial conditions) that make the experiment's data meaningful. None of that shows up
today.

**Approach:** content-only edit — no component, type, or prop changes. Replace `summary`
and the `responsibilities` array in the `subteam` object (lines 9–17). `icon`
(`FlaskConical`), `name`, `lead`, `leadLabel` stay as-is. Draft copy below, matching
sibling tone (one-sentence em-dash summary; 5 responsibilities, each a 2–4 word title
and one concrete sentence — see `FSW.tsx`, `ADCS.tsx`, `Structures.tsx`):

```
summary:
  "Payload runs SPICEsat's core experiment — measuring fuel slosh in microgravity and
  owning everything from the sensors to the control algorithms that fly it."

responsibilities:
  1. "Experiment hardware"
     "Design, mount, cable, and flight-harden the tank, camera, LED illumination, and
     torque/pressure sensors around the Raspberry Pi payload computer."
  2. "Payload flight software"
     "Run PFSW: talk to the OBC, convert ADCS commands into quaternions, and read out
     experiment parameters and commands to the control software."
  3. "Ground software & imaging"
     "Build the data pipeline and computer vision that check sloshing on camera against
     what the sensors measured."
  4. "Architecture & strategy"
     "Define reference frames (body, ECI, ECEF), model orbit and attitude in STK, and
     align sensor axes with the CAD model to set each run's initial conditions."
  5. "One cohesive team"
     "Split into software and general sections, but tightly coupled — everyone builds
     toward the same experiment."
```

This is the copy the user should review/adjust before it's typed into the file — the
Spec is the approval point, not the implementation.
